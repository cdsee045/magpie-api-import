# Magpie API 自动配置插件技术方案

按照[产品设计文档](https://chatgpt.com/space/page_414d3168ea188191a499ae8cc08b4c14)，实现面向 Windows 的 Magpie API 配置导入插件。目标是兼容官方版 Magpie，并通过插件市场安装：仅在“供应商 → 自定义供应商”页面识别剪贴板，验证接口可用后，由用户确认添加。

## 技术选型

| 部分 | 技术选择 | 作用 |
| --- | --- | --- |
| 界面 | HTML、CSS、TypeScript | 复用 Magpie 样式，实现识别状态、配置预览和确认交互。 |
| 插件业务 | TypeScript、Bun | 实现文本解析、流程控制、多 Key 选择、去重和取消处理。 |
| 本地能力 | Go、Windows 原生 API | 通过宿主授权接口读取文本和图片剪贴板，按需补充本地桥接。 |
| 截图识别 | 本地 Tesseract OCR | 图片转文字后进入统一解析流程，识别引擎和语言数据随发布方案准备。 |
| 接口验证 | 本地 HTTP 请求，优先复用 Magpie 现有验证逻辑 | 完成一次最小真实调用，记录验证通过的协议和模型。 |
| 配置与缓存 | Magpie 原有保存流程、内存缓存 | 保存供应商配置，短期记录去重和验证结果。 |
| 测试 | Bun test、Playwright；涉及 Go 时使用 Go test | 验证解析规则、交互流程、页面限制和宿主集成。 |

该组合贴合 Magpie 的 Bun 插件运行方式和 Go/Wails 桌面宿主。[插件文档](https://usemagpie.ai/docs/plugins)、[宿主依赖](https://github.com/yetone/magpie/blob/main/go.mod)。截图识别采用可在本地调用的 [Tesseract 引擎](https://github.com/tesseract-ocr/tesseract)，准确率需用实际截图验证。

## 主要处理流程

进入指定页面 → 读取剪贴板 → 文本解析或截图 OCR → 提取并补全配置 → 验证所选模型 → 询问是否添加 → 确认后保存。

无法识别时保持安静；信息不完整或验证失败时只显示页内提示；离开页面后取消后续处理，丢弃迟到结果。同一内容避免重复检测和提示，修改地址、Key、协议或模型后重新验证。

## Magpie 接入前提

首先验证官方版 Magpie 是否开放新建自定义供应商页面的进入和退出事件、受控剪贴板读取、验证及保存接口。根据公开插件文档，页面受沙箱限制，现有 provider 插槽对应已保存供应商的编辑器，尚不能据此确认能实现目标交互。[官方接口说明](https://usemagpie.ai/docs/plugins)

如果必须扩展宿主接口，需要相关改动被官方采纳并随新版 Magpie 发布，再声明插件最低支持版本。插件市场分发本身不会修改宿主程序，最终交付应满足用户安装插件即可使用。

## 数据处理与安全

整体在本机运行。插件仅保留必要设置和短期缓存，供应商配置交给 Magpie 保存；原始剪贴板、截图和 Key 不进入日志或 Git。剪贴板内容按数据解析，不执行其中的命令；验证请求仅发送到已识别的 API 地址，并限制超时及重复尝试。真实验证可能产生少量费用，OCR 无法确定的密钥字符交由用户补全。

## 开发与发布

1. 接入验证：先用 JSON 样例打通指定页面触发、验证、确认和保存，确认官方版兼容性。

2. MVP 实现：完善文本和 Base64 解析，再接入截图 OCR，完成逻辑、界面及真实宿主测试。

3. 插件发布：开发期从本地目录安装；稳定后发布到 npm 或 GitHub，补齐元数据、支持版本和使用说明，通过社区收录或 GitHub 插件发现机制展示。[发布说明](https://usemagpie.ai/docs/plugins#publishing-and-listing)

首版聚焦 Windows、常见 Chat Completions 兼容接口和单条配置导入。其他协议、批量导入、余额查询及自动切换供应商留待后续迭代。
