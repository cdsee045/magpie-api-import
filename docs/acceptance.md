运行 `npm run check` 验证模块和两套浏览器回归；`npm run test:magpie` 验证本机官方运行时。原生桌面窗口人工交互、真实供应商费用/额度、工具调用、远程浏览器和更早版本未覆盖。

用户提供的原图仅在本机内存中复现，确认可检出三条候选及两个地址；其中编码存在 OCR 字符误读，不能声称自动恢复了三个完整 Key。原图和真实凭证未加入仓库，自动回归使用同布局的虚构凭证 PNG。

0.2.5 使用用户本次提供的原图逐条切换及点击验证，确认缺少 Key/地址/人工核对时均在按钮下方显示原因，测试器禁止外部请求。模型第二组被 OCR 读成 `ds-41`，需要核对原文或使用接口模型列表；未声称截图能无人工修正地完成导入。

另经用户明确授权，对同一原图在内存中人工核对编码后做一次实际验收：两条 Key 的模型查询及单次、1 token 生成验证通过并返回确认结果；另一条在模型查询时收到 HTTP 401，未发起生成。不写入正式账号，不保留原图或凭证，不将第三方的当次可用性视为长期保证。该真实接口验收使用 Node.js 的正式导入会话；官方 Magpie/Bun 宿主的隔离验收仍使用虚构凭证，不能混称为真实供应商转发测试。
